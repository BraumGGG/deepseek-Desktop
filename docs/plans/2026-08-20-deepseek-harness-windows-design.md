# DeepSeek Harness Windows 便携版设计说明

## 背景与目标

将 DeepSeek Harness 封装成 Windows 10/11 x64 可直接双击运行的独立桌面窗口，面向免费分享和用户增长场景，优先控制包体积、启动稳定性和使用门槛。

成功标准：用户无需安装 Node.js 或执行命令，解压后双击 EXE 即可看到 Harness Web UI；关闭窗口后本地服务能够退出；启动失败时给出可理解的提示。

## 现状与约束

- 只支持 Windows 10/11 x64。
- 采用便携 ZIP，不制作复杂安装器。
- 不实现账号系统、在线后台、自动更新、插件市场、托盘、多平台支持。
- Harness 版本必须锁定，避免上游 Developer Preview 更新导致不可复现。
- 本地服务只监听 `127.0.0.1`，不对局域网开放。

## 方案对比

### 方案一：Tauri + Node sidecar（推荐）

- 优点：桌面壳小，使用系统 WebView2，适合便携分发；窗口体验独立；可携带固定 Node 运行时和 Harness 构建产物。
- 缺点：需要 Rust 工具链；sidecar 路径和进程管理需要一次性处理。

### 方案二：Electron

- 优点：Node/Chromium 集成直接，开发资料多。
- 缺点：内置 Chromium 导致包体积明显更大，不符合“轻量免费分享”目标。

### 方案三：浏览器启动器

- 优点：实现最简单。
- 缺点：不是独立桌面窗口，体验不符合已确认目标。

## 推荐方案

采用 Tauri 桌面壳，内置固定版本 Node runtime、Harness 构建产物和依赖。发布形式为解压即用的 ZIP，首版只提供 x64 版本。

## 详细设计

### 架构

```text
DeepSeekHarness.exe (Tauri)
  ├─ 启动 harness/runtime/node.exe
  ├─ 传入本地配置和随机可用端口
  ├─ 轮询 127.0.0.1:<port> 的健康状态
  └─ 使用系统 WebView2 加载本地 Web UI
```

### 关键组件

- Tauri 主进程：窗口创建、端口选择、子进程生命周期管理。
- Harness 运行目录：固定版本的构建输出和生产依赖。
- Node runtime：随 ZIP 分发，不依赖系统 Node.js。
- 配置目录：放在用户目录，避免安装目录不可写导致配置丢失。
- 启动诊断：将服务标准输出和错误输出写入 `logs/`，失败时弹出日志路径。

### 数据流

1. 用户双击 EXE。
2. 主进程确认单实例并选择空闲端口。
3. 启动 Harness Web 服务，传入端口和用户数据目录。
4. 主进程轮询服务可用性，最长等待约 30 秒。
5. 服务可用后创建或显示桌面窗口。
6. 窗口关闭时终止 Harness 子进程并回收句柄。

### 异常处理

- 端口占用：自动换用随机端口，不要求用户修改配置。
- WebView2 缺失：显示安装提示和官方运行时名称。
- Harness 启动失败：显示简短错误，并提供日志文件路径。
- 启动超时：终止子进程，避免残留后台进程。
- 重复启动：激活已有窗口，不再创建第二个服务。

### 测试策略

- 在无 Node.js 的 Windows 10/11 x64 环境验证冷启动。
- 验证端口占用、配置目录首次创建、服务启动超时和窗口关闭。
- 验证 ZIP 解压路径包含中文和空格时仍能启动。
- 验证重复双击只有一个实例。
- 构建后统计 ZIP 大小，目标为 150 MB 以内，必要时再做依赖裁剪。

## 风险与待确认项

- Harness 是否能以固定构建产物脱离源码目录运行，需要在实现阶段验证。
- Harness 是否包含原生 Node 模块，可能影响 Windows 打包。
- WebView2 在目标系统上的实际预装覆盖率，需要准备清晰的缺失提示。
- 许可证、NOTICE 和第三方依赖清单必须随发布包保留。
